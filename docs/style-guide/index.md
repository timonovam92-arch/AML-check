# Стайлгайд для технической документации

**Версия:** 1.0
**Автор:** Марина Тимонова

## 1. Введение

### 1.1. Для чего этот документ

Этот стайлгайд устанавливает единые правила для создания и оформления технической документации. Его цель — обеспечить консистентность, ясность и удобство всех текстов, которые я создаю в рамках своего портфолио.

### 1.2. Для кого этот документ

*   Для меня самой (как рабочий инструмент и напоминание).
*   Для коллег, которые могут подключаться к моим проектам.
*   Для работодателей (как демонстрация моего системного подхода к документации).

### 1.3. Область применения

Правила, описанные в этом гайде, применяются ко всей моей технической документации, включая руководства пользователя, инструкции по установке, описание API и внутренние базы знаний.

## 2. Основные принципы хорошей документации

*   **Польза.** Каждый документ должен отвечать на вопрос «Зачем это нужно?» и решать конкретную задачу пользователя.
*   **Ясность.** Пиши просто, краткими предложениями. Избегай сложных конструкций и неоднозначных терминов.
*   **Структура.** Информация должна быть организована логически. Используй заголовки, списки и таблицы для наглядности.
*   **Единообразие.** Все документы должны следовать единым правилам оформления и использования терминологии.

## 3. Структура стайлгайда

*   **Правила оформления текста.** Заголовки, списки, таблицы, выделения.
*   **Язык и терминология.** Глоссарий, сокращения, тон изложения.
*   **Визуальные элементы.** Схемы, скриншоты, видео.
*   **Структура документов.** Шаблоны для разных типов (инструкция, руководство, API-документ).
*   **Процесс работы с контентом.** Как создавать, рецензировать и обновлять документы.
